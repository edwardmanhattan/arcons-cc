What this document set explains

The application is a wall display for the live maritime picture. The repository holds more than one program. The wall is the main program. The desk writes fixes. The phone controls the wall. The relay carries the phone's lines. One gate proves the code.

This document set answers three questions:

  1. Which parts exist, and which part owns which state?
  2. How does one fix move from Minos to a pixel on the wall?
  3. How does a reader know that a claim is true?

The answer to the third question is a command. A ticket is done when scripts/verify.sh exits 0. The document uses file names and function names. A reader can open the code and compare it with the text.

The system in one picture

Minos is the backend. Minos is not in this repository. The wall reads Minos. The wall does not write Minos. The desk is the one program that writes a fix.

The wall

Root package. Reads Minos. Draws the picture. Answers the control plane. Does not write Minos.

The desk

crates/desk. Reads the picture. Writes relayed fixes for a batch of units.

The phone

clients/phone. Sends intents. Reads the projection. Holds no Minos credential.

The relay

tools/dev-relay. Joins the phone and the wall in development. Not the contract.

The gate

scripts/verify.sh. One command. Format, lints, tests, captures, budgets.

The wall is the authority for its own arrangement. A viewer is a second wall process that draws the authority's scenes. A viewer holds no Minos credential and opens no Minos socket.

The one rule to remember

The view loop never blocks. Each slow part owns a thread. The slow parts send messages to the view loop. The view loop owns the state and builds the next frame.

One code shape to remember

The library says why the modules are separate. Read the first two rules. Then read the module list. A new module must not break either rule.

The list is not a layer diagram. data does not call ui. ui reads units. live and data send values to ui. control changes ui::State through one function. This direction keeps the view loop free of network and engine work.
