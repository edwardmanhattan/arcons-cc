Architecture V: scenes, captures, and the gate

The wall is a picture. A picture needs a witness. This page shows how the repository turns a named state into pixels, compares the pixels, asks geometry questions, and decides that a ticket is done with one command.

Code: src/scene.rs, src/verify.rs, scripts/verify.sh, scripts/capture.sh, scripts/assert.sh. Diagrams rendered with Pele.

Overview Runtime Picture Control Verification

The gate

The gate is one command. It is scripts/verify.sh. CI runs the same command. A human runs the same command. CI and a human cannot run different checks.

The gate needs no network, no display, and no GPU beyond a software Vulkan driver. A check that needs one of those does not belong in the gate. It belongs in a ticket that says so.

The one hole, named

The gate does not build the map feature. MapLibre's C++ needs a compiler and a network download. CI's map jobs compile the map-gated code on macOS and Windows. Set VERIFY_WITH_MAP=1 to close the hole on a local machine. A red map job is a red pull request.

A scene is a named state

A scene is a function that changes a State. Rune owns the scene list and the virtual clock. The wall supplies the fixture and the functions. A scene has no network, no credential, and no wall clock.

The fixture is wire-shaped. fixtures/scenes/feed.json is the GET /live-feed/positions envelope. A scene parses it with the same FeedPosition type that the REST client uses. A fixture written from the wall's own types would prove only that the wall agrees with itself.

Rune starts a scene at logical time zero. poll receives that virtual clock, not the system clock. Two runs of the same scene therefore draw the same ages, the same travel positions, and the same text. This is INV-11.

A capture is a witness

A capture renders one scene to a PNG with no window. The flags are written in scripts/capture.sh and nowhere else. CI and a human use the same flags.

--at 2 is two seconds of virtual time. A scene with a travel animation has settled by then. A capture at zero could be right for the wrong reason.

The script renders the scene two times. It compares the bytes. If the two PNGs differ, the gate fails before it compares a golden. Nondeterminism is a defect in the renderer, and no golden can repair it.

A golden is a reference PNG in fixtures/golden/. A human updates a golden with scripts/capture.sh --update-goldens. The gate never updates a golden. A change to a golden is a visible commit that a reviewer can inspect.

Golden comparison has numbers

Two rasterisers do not produce identical pixels. The golden comparison therefore has bounds. The bounds are measured, then given a margin. Each run prints the numbers.

A scene with scaled text can need a larger rounding allowance. The exception stays in golden_bounds(scene), beside the measurement that caused it. The change budget stays at 200. A panel that moved must fail, even when its pixels are only one step different.

Why two checks

A golden says that the picture changed. It does not say what changed. The assertion says “no marker within 8 px of this projection” or “the stale marker is dimmer than the live one”. The two checks answer different questions.

Pixel and structure assertions

An assertion reads a PNG and asks a question with a number. The colours come from ui::tokens. The geometry comes from map::geometry::project. An assertion cannot outlive the palette or the projection that it describes.

A centroid moves with the marker. A check for “any matching ink near the point” would pass when a marker moved five pixels. The tolerance is 8 pixels. Eight is measured: the panel border and Rune's layout put a correct marker about four pixels from the raw projection. Eight is smaller than the grid spacing and much smaller than a wrong camera.

assert_scene asks about the picture: ink, colours, positions, and panel edges. assert_structure asks about the element tree: a pane exists, a card is inside the window, a menu row is reachable. A capture can be right in its pixels and wrong in its structure.

The command a human runs

scripts/assert.sh out/picture.png prints one line for each question and exits non-zero on the first wrong answer. It runs the same --assert path that the gate runs.

How to add a scene

  1. Add a fixture in fixtures/scenes/. Use the wire envelope, not a wall type.
  2. Add a function in src/scene.rs. Load the fixture. Set the camera. Set no clock.
  3. Add the name to SCENES. A scene that exists is a scene the gate renders.
  4. Run scripts/capture.sh NAME. The first run has no golden, so the gate fails here.
  5. Look at out/NAME.png. If the picture is correct, a human runs scripts/capture.sh --update-goldens NAME.
  6. Add the pixel and structure questions to src/verify.rs. A golden alone does not say what is wrong.
  7. Run scripts/verify.sh. Paste its last lines in the pull request.

The order matters. A golden generated before a human looks at the picture makes the defect the reference. The repository has one example: a scene drew a NATO symbol over a golden for ten days (#54).

CI, and the two map jobs

CI runs scripts/verify.sh in one Linux job. It also runs three platform checks:

jobcommandstate
check (ubuntu, macos, windows)cargo check --all-targets, fmt, clippyblocks
map (macos-latest)cargo clippy -p arcons-cc -p desk --features map -D warningsblocks
map (windows-latest)the same commandadvisory; the vendored engine refuses the Windows target
verifyscripts/verify.shblocks
phone, phone-android, phone-iosDart tests, Flutter tests, APK, iOS buildseparate jobs

The map exception is real. The gate cannot build MapLibre's C++ on every machine, so the map jobs are the only proof that the map-gated code compiles. A red map (macos-latest) is a red pull request. #152 is the reason: a field became a method, four map-gated sites were left behind, and the feature did not compile for five merges while the gate was green.

CI uploads every capture when it fails. A pixel difference is the one failure that a log line cannot explain. The next person diffs the images instead of guessing.

The rule

A ticket is done when the gate is green. A screenshot is not proof. A compile is not proof. The last lines of scripts/verify.sh are proof.
