Summary

The project draws the live maritime picture on a wall. The wall shows the units and their fixes. Minos is the backend. Minos is not in this repository. The apps use a deployment's URL.

The wall

Repository root. Reads Minos. Draws the picture. Does not write Minos.

The desk

crates/desk. Reads Minos. Writes one fix for one unit.

The phone

clients/phone. Controls the wall. Does not read Minos.

The relay

tools/dev-relay. Carries the phone's lines to the wall in development.

The gate

scripts/verify.sh. Proves the wall and the desk.

The wall

  1. The wall starts. The config and the credential are read.
  2. The data thread reads GET /live-feed/positions.
  3. The live thread connects to Centrifugo. It subscribes to live-feed.
  4. The map thread draws a frame. The UI thread draws the picture, the panes, the cards, and the menus.
  5. A live fix arrives. The live thread sends it to the UI. The UI draws the fix.
  6. A reconnect starts a new read. There is no history on live-feed.
  7. The control plane receives intents. The local client, or the phone through the relay, sends them.

The wall is read-only for Minos. The wall writes only its own arrangement and settings on disk.

The desk

  1. The desk starts. The deployment and the credential are read.
  2. The read worker reads GET /live-feed/positions.
  3. The read worker writes desk-picture.json. The UI paints the cache first.
  4. The person at the desk selects a unit and enters a fix.
  5. The send worker sends one POST /live-feed/fixes/relayed for one unit.
  6. Minos answers for that unit: 201 with latest, or 400, 401, 403, 404, 422.
  7. Minos records the fix. Minos publishes the fix. The wall receives it.
  8. The wall shows the manual fix: the hollow provenance ring and the card line "reported by X for Y".

WARNING: The desk sends a real fix. Use a test deployment or a named test unit.

A 403 can mean "this unit has no commander" or "this account lacks report_as". These are refusals, not bugs.

The phone

  1. The phone pairs with the wall. The wall shows six digits. The phone sends pair.claim.
  2. The phone reads the wall's projection. It asks for a watch after the read.
  3. The phone sends intents: focus, drop, resize, follow, and the other verbs in docs/control.md.
  4. The wall applies the intent. The wall publishes the new projection.
  5. The phone reads the projection. It does not receive the picture.

The phone does not read Minos. It controls the wall.

The relay

The wall dials out to the relay. The phone dials the relay. The relay carries JSON lines. In development, tools/dev-relay is the relay.

WARNING: The development relay has no authentication, no TLS, and no persistence. Do not use it on a deployment.

Run each app

1. Prepare the configuration

The wall and the desk use the same files. The program reads the environment first, then the file.

Make the directory:

mkdir -p "$XDG_CONFIG_HOME/arcons-cc"

Write config.toml:

minos_url      = "https://HOST/api/v1"
centrifugo_url = "wss://HOST/connection/websocket"
credentials    = "credentials.toml"
map_center     = [-6.10, 106.88]
map_zoom       = 11.0
stale_after_s  = 300

Write credentials.toml:

refresh_token = "…"

Use refresh_token, or identifier and password.

Set the mode:

chmod 600 "$XDG_CONFIG_HOME/arcons-cc/credentials.toml"

WARNING: The credential file must have mode 0600. The wall and the desk refuse a file with a group or other permission bit.

You can use environment variables instead:

MINOS_BASE_URL=https://HOST/api/v1
MINOS_SOCKET_URL=wss://HOST/connection/websocket
MINOS_REFRESH_TOKEN=…

The desk can use MINOS_IDENTIFIER and MINOS_PASSWORD.

The permissions:

  • The wall account needs read on /system/live-feed and /system/units.
  • The desk account needs read on /system/live-feed and report_as on /system/live-feed.

Check the wall:

cargo run -- --self-check

Exit codes: 0 ok, 1 config, 2 credential, 3 login, 4 REST, 5 socket, 6 seed.

2. Run the wall

Use the map feature to see the map:

cargo run --features map

Use no map for the gate build:

cargo run

Useful flags:

cargo run --features map -- --fullscreen
cargo run --features map -- --window-size 1920x1080
cargo run -- --version
cargo run -- --self-check
cargo run -- --scene <scene> --snap out/<scene>.png
cargo run -- --record
cargo run -- ctl pane focus 2

Note: The first map build is slow. The build machine uses a prebuilt MapLibre core. Read docs/build-environment.md before you change a profile, jobs, or the target directory.

Note: The control socket is local and Unix only. Set ARCONS_CONTROL=0 to turn the control plane off.

Note: The wall can use a relay. Set ARCONS_RELAY_URL=tcp://HOST:PORT.

3. Run the desk

Use the map feature for the chart:

cargo run -p desk --features map

Use no map:

cargo run -p desk

Useful commands:

cargo run -p desk -- --self-check
cargo run -p desk -- --new-device-id
cargo run -p desk -- --scenes
cargo run -p desk -- --scene <scene> --snap out/desk-<scene>.png

Note: The desk's --self-check prints the config directory and the device id. The desk checks the deployment and the credential at the first read or send.

The desk writes these files:

  • $XDG_CONFIG_HOME/arcons-cc/desk-device-id
  • $XDG_CONFIG_HOME/arcons-cc/desk-picture.json

4. Run the phone

Test the package. This needs no UI toolkit:

cd clients/phone
dart pub get
dart analyze --fatal-infos
dart test

Test the app:

cd clients/phone/app
flutter pub get
flutter analyze
flutter test

Run the app against a relay:

cd clients/phone/app
flutter run --dart-define=ARCONS_RELAY=tcp://HOST:PORT

Note: The camera and the platform key store compile in CI. A human with a phone must test them. See clients/phone/README.md.

5. Run the development relay and the phone

Start the relay:

dart run tools/dev-relay/bin/main.dart --host 0.0.0.0 --port 7000 --verbose

Start the wall with the relay:

ARCONS_RELAY_URL=tcp://127.0.0.1:7000 cargo run --features map

Start the phone with the relay:

cd clients/phone/app
flutter run --dart-define=ARCONS_RELAY=tcp://<LAN-IP>:7000

Show the pairing code on the wall:

cargo run -- ctl pair begin

Type the six digits on the phone. To revoke the phone:

cargo run -- ctl pair forget <name>

The gate

Run the gate:

scripts/verify.sh

Use the fast inner loop:

scripts/verify.sh --fast

Build the map feature too:

VERIFY_WITH_MAP=1 scripts/verify.sh

The gate runs these checks:

  • cargo fmt --check
  • cargo clippy -D warnings
  • cargo test
  • the map feature, if requested
  • the spec snapshot
  • the wall captures and assertions
  • the desk captures
  • the frame CPU and memory budgets

Useful capture commands:

scripts/capture.sh <scene>
scripts/capture.sh --update-goldens
scripts/assert.sh out/<scene>.png
scripts/capture-desk.sh <scene>
scripts/capture-desk.sh --update-goldens

WARNING: A golden change needs a human review. Use --update-goldens only after you read the picture diff.

Replay the control recording:

scripts/conformance.sh fixtures/control/session.jsonl

Record the control fixtures:

cargo run -- --record

Record the desk report exchanges:

scripts/record-desk-report.sh

WARNING: The --write option of scripts/record-desk-report.sh writes a real fix. A human must approve it.

The phone has separate CI jobs:

  • phone-android
  • phone-ios
